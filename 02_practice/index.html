개요 — STEP 02 학습 내용

이론적 배경

단일 state에서는 모든 리소스가 하나의 의존 그래프가 됩니다 — aws_subnet의 vpc_id = aws_vpc.x.id 같은 직접 참조가 연결 고리를 만들고, Terraform이 생성 순서를 자동으로 계산합니다. 계층별 state 분리(remote_state)는 11_app_pipeline에서 다룹니다.

학습 목표

  • 단계별 독립 state로 인프라를 층별로 구축할 수 있다
  • 같은 state 안에서 리소스가 서로를 직접 참조하는 의존 그래프를 읽을 수 있다
  • apply 중 발생하는 실제 오류(키페어·버전·고아 리소스)를 진단·해결할 수 있다
  • AWS CLI로 생성 결과를 검증할 수 있다

핵심 내용

  • 01: provider·버전 고정
  • 02~06: 네트워크 (VPC·서브넷·IGW·NGW·라우팅)
  • 07~09: 컴퓨트 (SG·EC2 배스천·RDS)
  • destroy는 apply의 역순으로 자동 계산됨

산출물 · 완료 기준

  • 4단계로 나뉜 state 기반 인프라
  • check.sh로 생성한 결과 리포트
  • [ ] 각 단계가 독립 state를 갖는 이유를 설명할 수 있다
  • [ ] 리소스 간 직접 참조(aws_vpc.x.id)로 의존 그래프가 만들어지는 걸 이해한다
  • [ ] apply 오류 시 state와 AWS 실제 상태를 대조해 진단할 수 있다
  • [ ] destroy 역순 규칙을 안다

실습 — STEP 02 실행

아래 명령은 터미널에서 프로젝트 루트(aws-tf/) 기준으로 실행합니다.

실행 방법

복사 버튼으로 명령을 가져간 뒤 터미널에 붙여넣기 (⌘V) 하세요.

terraform init

실습 단계

  1. plan 출력에서 리소스 생성 순서(의존 그래프) 확인
  2. apply 후 terraform output으로 접속 정보 확인
  3. check.sh 리포트로 state ↔ AWS 실체 대조
  4. 실습 후 반드시 역순 destroy (과금 방지)

# ============================================================
# 01-provider.tf — Terraform 코어·프로바이더 선언
# - terraform 블록: 실행에 필요한 코어 버전과 프로바이더를 고정
# - provider 블록: 실제 AWS 접속 설정 (리전)
# 인증 정보는 코드에 적지 않고 ~/.aws 자격증명 또는 환경변수를 사용
# ============================================================

terraform {
  required_version = ">= 1.0.0, <2.0.0" # Terraform 1.x 버전대만 허용

  required_providers {
    aws = {
      source  = "hashicorp/aws" # 레지스트리 주소 (네임스페이스/이름)
      version = "~> 5.0"        # 5.x만 허용 — 6.0 메이저 변경 차단
    }
  }
}

provider "aws" {
  region = "ap-northeast-2" # Asia Pacific (Seoul)
}

# ============================================================
# 02-vpc.tf — VPC (Virtual Private Cloud)
# 이 인프라 전체가 들어갈 논리적 네트워크 공간
# ============================================================

resource "aws_vpc" "terraform_vpc" {
  cidr_block           = "10.200.0.0/16" # VPC 전체 IP 대역 (약 65,000개 IP)
  enable_dns_support   = true            # VPC 내부 DNS 해석 활성화
  enable_dns_hostnames = true            # 인스턴스에 DNS 호스트명 부여

  tags = {
    "Name" = "terraform-vpc"
  }
}

# ============================================================
# 03-subnet.tf — 서브넷 (Subnet)
# VPC의 IP 대역을 가용영역별로 나눈 구획.
# - 퍼블릭: IGW로 직접 나가는 서브넷 (map_public_ip_on_launch = true)
# - 프라이빗: 외부 직접 접근 불가, NGW 경유 아웃바운드만 가능
# 배치 규칙: AZ당 pub 1개 + pri 1개 — 2개 AZ라 총 4개
# ============================================================

# Public Subnet — ap-northeast-2a
resource "aws_subnet" "terraform_pub_subnet_2a" {
  vpc_id                  = aws_vpc.terraform_vpc.id # 어느 VPC 안에 만들지
  cidr_block              = "10.200.1.0/24"          # VPC 대역(10.200.0.0/16) 안의 /24
  availability_zone       = "ap-northeast-2a"        # 서브넷은 반드시 1개 AZ에 소속
  map_public_ip_on_launch = true                     # 이 서브넷의 인스턴스에 공인 IP 자동 부여

  tags = {
    Name = "terraform-pub-subnet-2a"
  }
}

# Public Subnet — ap-northeast-2c (다른 AZ — 장애 대비 이중화의 기본)
resource "aws_subnet" "terraform_pub_subnet_2c" {
  vpc_id                  = aws_vpc.terraform_vpc.id
  cidr_block              = "10.200.2.0/24"
  availability_zone       = "ap-northeast-2c"
  map_public_ip_on_launch = true

  tags = {
    Name = "terraform-pub-subnet-2c"
  }
}

# Private Subnet — ap-northeast-2a
resource "aws_subnet" "terraform_pri_subnet_2a" {
  vpc_id            = aws_vpc.terraform_vpc.id
  cidr_block        = "10.200.11.0/24" # pub과 겹치지 않는 대역으로 구분
  availability_zone = "ap-northeast-2a"
  # map_public_ip_on_launch 생략 = false — 공인 IP가 없어 외부에서 직접 접근 불가

  tags = {
    Name = "terraform-pri-subnet-2a"
  }
}

# Private Subnet — ap-northeast-2c
resource "aws_subnet" "terraform_pri_subnet_2c" {
  vpc_id            = aws_vpc.terraform_vpc.id
  cidr_block        = "10.200.12.0/24"
  availability_zone = "ap-northeast-2c"

  tags = {
    Name = "terraform-pri-subnet-2c"
  }
}

# ============================================================
# 04-igw.tf — 인터넷 게이트웨이 (IGW)
# VPC와 인터넷 사이의 출입구.
# 퍼블릭 서브넷이 외부와 통신하려면 IGW + 라우팅 테이블의 0.0.0.0/0 경로가 필요
# ============================================================

resource "aws_internet_gateway" "terraform_igw" {
  vpc_id = aws_vpc.terraform_vpc.id # 이 VPC에 IGW를 연결

  tags = {
    Name = "terraform-igw" # AWS 태그 값은 하이픈 OK
  }
}

# ============================================================
# 05-ngw.tf — NAT 게이트웨이 + EIP
#
# **NGW**
#
# NAT Gateway의 약자로 VPC 내에서 프라이빗 서브넷에 있는 리소스들이 인터넷에 접근할 수 있도록 도와주는 서비스
# NAT는 Network Address Translation : 프라이빗 네트워크의 사설 IP를 공인 IP로 변환하여 외부와의 통신을 가능하게 함
#
# **EIP**
# NAT Gateway에 고정된 퍼블릭 IP 주소를 제공
# EIP가 없으면 NAT Gateway가 인터넷과 연결되지 않고, 프라이빗 서브넷에 있는 리소스는 외부와 통신이 불가함
# ============================================================

# Elastic IP — NAT 게이트웨이가 외부에 보여줄 고정 공인 IP
resource "aws_eip" "terraform_eip" {
  domain = "vpc"
}

# NAT 게이트웨이 — 반드시 "퍼블릭" 서브넷에 배치해야 프라이빗 서브넷의
# 아웃바운드 트래픽을 중계할 수 있다
resource "aws_nat_gateway" "terraform_ngw" {
  allocation_id = aws_eip.terraform_eip.id # 위에서 만든 EIP를 이 NGW에 연결
  subnet_id     = aws_subnet.terraform_pub_subnet_2a.id
  tags = {
    "Name" = "terraform-ngw"
  }
}

# ============================================================
# 06-routing-table.tf — 라우팅 테이블·라우팅·서브넷 연결
#
# 구조도:
#   10.200.0.0/16 VPC
#   │
#   ├─ Subnet: 10.200.1.0/24 (terraform_pub_subnet_2a)
#   │     └─ Route Table: terraform_pub_rt → IGW
#   ├─ Subnet: 10.200.2.0/24 (terraform_pub_subnet_2c)
#   │     └─ Route Table: terraform_pub_rt → IGW
#   │
#   ├─ Subnet: 10.200.11.0/24 (terraform_pri_subnet_2a)
#   │     └─ Route Table: terraform_pri_rt → NAT GW
#   └─ Subnet: 10.200.12.0/24 (terraform_pri_subnet_2c)
#         └─ Route Table: terraform_pri_rt → NAT GW
#
# 흐름: route_table 생성 → route(목적지 경로) 추가 → 서브넷에 association
# ============================================================

# 라우팅 테이블 — 서브넷 트래픽의 목적지 규칙을 담는 컨테이너
resource "aws_route_table" "terraform_pub_rt" {
  vpc_id = aws_vpc.terraform_vpc.id

  tags = {
    "Name" = "terraform-pub-rt"
  }
}

resource "aws_route_table" "terraform_pri_rt" {
  vpc_id = aws_vpc.terraform_vpc.id

  tags = {
    "Name" = "terraform-pri-rt"
  }
}

# 라우팅 — 퍼블릭: 모든 외부 트래픽(0.0.0.0/0)을 IGW로 보냄
resource "aws_route" "terraform_pub_rt" {
  route_table_id         = aws_route_table.terraform_pub_rt.id
  destination_cidr_block = "0.0.0.0/0"
  gateway_id             = aws_internet_gateway.terraform_igw.id
}

# 라우팅 — 프라이빗: 외부로 나가는 트래픽은 NAT 게이트웨이 경유
# (인터넷→내부 방향의 신규 연결은 불가, 내부→외부 응답만 통과)
resource "aws_route" "terraform_pri_rt" {
  route_table_id         = aws_route_table.terraform_pri_rt.id
  destination_cidr_block = "0.0.0.0/0"
  nat_gateway_id         = aws_nat_gateway.terraform_ngw.id
}

# 명시적 서브넷 연결 — 테이블과 서브넷을 짝지어야 규칙이 실제로 적용됨
resource "aws_route_table_association" "terraform_pub_rt_associate_2a" {
  subnet_id      = aws_subnet.terraform_pub_subnet_2a.id
  route_table_id = aws_route_table.terraform_pub_rt.id
}

resource "aws_route_table_association" "terraform_pub_rt_associate_2c" {
  subnet_id      = aws_subnet.terraform_pub_subnet_2c.id
  route_table_id = aws_route_table.terraform_pub_rt.id
}

resource "aws_route_table_association" "terraform_pri_rt_associate_2a" {
  subnet_id      = aws_subnet.terraform_pri_subnet_2a.id
  route_table_id = aws_route_table.terraform_pri_rt.id
}

resource "aws_route_table_association" "terraform_pri_rt_associate_2c" {
  subnet_id      = aws_subnet.terraform_pri_subnet_2c.id
  route_table_id = aws_route_table.terraform_pri_rt.id
}

# ============================================================
# 07-sg-ec2-rds.tf — 보안 그룹 (Security Group)
# 인스턴스 수준의 가상 방화벽. ingress=들어오는 트래픽, egress=나가는 트래픽
# ※ cidr_blocks = 0.0.0.0/0 은 전체 인터넷 허용 — 실습용 설정이며
#   운영 환경에서는 허용 범위를 좁히는 것이 원칙
# ============================================================

# Bastion SG — 배스천(경유 접속용) 서버에 적용할 규칙
resource "aws_security_group" "terraform_sg_bastion" {
  name        = "terraform-sg-bastion"
  description = "for Bastion Server"
  vpc_id      = aws_vpc.terraform_vpc.id
  tags = {
    "Name" = "terraform-sg-bastion"
  }

  # ICMP — ping 응답 허용 (네트워크 연결 확인용)
  ingress {
    from_port   = -1
    to_port     = -1
    protocol    = "icmp"
    cidr_blocks = ["0.0.0.0/0"]
    description = "for ping"
  }

  # SSH — 원격 접속용 22번 포트
  ingress {

    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]

  }

  # HTTP — 웹 서비스 80번 포트

    to_port     = 443

    cidr_blocks = ["0.0.0.0/0"]

  }

  # MySQL/MariaDB — DB 접속용 3306번 포트
  ingress {
    from_port   = 3306
    to_port     = 3306
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
    description = "for DB"
  }

  # 아웃바운드는 전부 허용 — 패키지 설치·외부 API 호출 등을 위해
  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1" # -1 = 모든 프로토콜
    cidr_blocks = ["0.0.0.0/0"]
  }
}

#!/usr/bin/env bash
# 03_aws 실습 결과 확인 스크립트
# terraform state + AWS CLI 조회 결과를 하나의 HTML 리포트로 생성한다.
# 사용법: ./check.sh [출력파일]   (기본: report.html)
set -u
cd "$(dirname "$0")"

REGION="ap-northeast-2"
OUT="${1:-report.html}"
NOW="$(date '+%Y-%m-%d %H:%M:%S')"

# 각 항목: "제목|명령어 문자열" — 실패해도 계속 진행
run() {
  local title="$1"; shift
  {
    echo "<h2>$title</h2>"
    echo "<pre>"
    "$@" 2>&1 | sed -e 's/&/\&amp;/g' -e 's/</\&lt;/g' -e 's/>/\&gt;/g'
    echo "</pre>"
  } >> "$OUT.tmp"
}

cat > "$OUT.tmp" <<EOF
<!DOCTYPE html>
<html lang="ko">
<head>
<meta charset="utf-8">
<title>03_aws 실습 결과 — $NOW</title>
<style>
  body { font-family: -apple-system, 'Apple SD Gothic Neo', 'Noto Sans KR', sans-serif;
         background: #f8fafc; color: #122033; margin: 0; }
  .bar { height: 10px; background: #1769aa; }
  main { max-width: 1100px; margin: 0 auto; padding: 32px 40px 60px; }
  h1 { font-size: 28px; margin: 8px 0 4px; }
  .sub { color: #516174; font-size: 14px; margin-bottom: 28px; }
  h2 { font-size: 17px; color: #1769aa; border-bottom: 1px solid #c9d5e1;
       padding-bottom: 6px; margin-top: 32px; }
  pre { background: #fff; border: 1px solid #c9d5e1; border-radius: 8px;
        padding: 14px 16px; font-family: ui-monospace, Menlo, 'SF Mono', monospace;
        font-size: 12.5px; overflow-x: auto; white-space: pre; }
  .warn { color: #b86e00; }
</style>
</head>
<body>
<div class="bar"></div>
<main>
<h1>03_aws — Terraform 실습 결과</h1>
<p class="sub">생성 시각: $NOW · 리전: $REGION · 디렉터리: $(pwd)</p>
EOF

# --- Terraform 쪽 ---
run "terraform state list" terraform state list
run "terraform validate" terraform validate

# --- AWS CLI 쪽 ---
run "VPC" aws ec2 describe-vpcs --region "$REGION" \
  --query 'Vpcs[*].[VpcId,CidrBlock,Tags[?Key==`Name`].Value|[0]]' --output table

run "Subnets" aws ec2 describe-subnets --region "$REGION" \
  --query 'Subnets[*].[SubnetId,CidrBlock,AvailabilityZone,Tags[?Key==`Name`].Value|[0]]' --output table

run "Internet Gateway" aws ec2 describe-internet-gateways --region "$REGION" \
  --query 'InternetGateways[*].[InternetGatewayId,Attachments[0].VpcId]' --output table

run "NAT Gateway" aws ec2 describe-nat-gateways --region "$REGION" \
  --filter "Name=state,Values=available" \
  --query 'NatGateways[*].[NatGatewayId,State,SubnetId]' --output table

run "Elastic IP" aws ec2 describe-addresses --region "$REGION" \
  --query 'Addresses[*].[AllocationId,PublicIp]' --output table

run "Route Tables" aws ec2 describe-route-tables --region "$REGION" \
  --query 'RouteTables[*].[RouteTableId,Routes[*].[DestinationCidrBlock,GatewayId,NatGatewayId]|[]]' --output table

run "Security Groups" aws ec2 describe-security-groups --region "$REGION" \
  --query 'SecurityGroups[*].[GroupId,GroupName,Description]' --output table

run "EC2 (running)" aws ec2 describe-instances --region "$REGION" \
  --filters "Name=instance-state-name,Values=running" \
  --query 'Reservations[*].Instances[*].[InstanceId,InstanceType,PublicIpAddress,KeyName,Tags[?Key==`Name`].Value|[0]]' --output table

run "RDS" aws rds describe-db-instances --region "$REGION" \
  --query 'DBInstances[*].[DBInstanceIdentifier,DBInstanceStatus,Engine,EngineVersion,Endpoint.Address]' --output table

run "Key Pairs" aws ec2 describe-key-pairs --region "$REGION" \
  --query 'KeyPairs[*].[KeyName,CreateTime]' --output table

echo '</main></body></html>' >> "$OUT.tmp"
mv "$OUT.tmp" "$OUT"
echo "생성 완료: $(pwd)/$OUT"
